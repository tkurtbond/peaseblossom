# rtl/vax

poc's runtime for the VAX/VMS target (`PLAN.md` Phase 16), in Oberon-2
over a thin MACRO-32 layer (`doc/developer/vax-macro32-backend.md`,
section 15). A program finds these modules as source, `poc -target
vax-dec-vms -import-path <this directory> -build ...` compiling the ones
it imports with it, or in the library `POCRTL` (Phase 17 step 1,
section 18), made by `poc -target vax-dec-vms -library POCRTL
rtl/vax/*.Mod rtl/vax/PocRtl.mar`. Which of `rtl/llvm`'s modules are to
come, and what each needs, is in `doc/research/vms-module-inventory.md`.

- `PocRtl.mar`, MACRO-32, which a program poc builds for `vax-dec-vms`
  links as `POCRTL.OBJ`. Its `POC_STRCMP`, `POC_HMUL`, `POC_HDIV` and
  `POC_HMOD` are the final routines, as are `POC_CDIV`, `POC_CMOD` and
  `POC_CTOG`, the `CARD64` division and conversion to G_floating
  (section 20.1, proposals 3 and 4). `POC_TRAP` writes the trap's
  message to `SYS$ERROR` and exits with the trap's status, and
  `POC_HALT` exits with `HALT`'s (section 14, item 10). `POC_ROOTS`
  lists each module's root table, in every program. The rest are what
  the modules below call: writing records to `SYS$OUTPUT` and
  `SYS$ERROR`, logical names, DCL symbols, `$ERASE`, `$PARSE`,
  `LIB$CREATE_DIR`, `$SETDDIR`, `$GETJPI`, `LIB$GET_FOREIGN`, RMS file
  access for `Files`, and memory, saved registers, an exit handler and the paging
  file quota for the collector.
- `Out.Mod` and `Err.Mod`, `rtl/llvm`'s whole interface, write to
  `SYS$OUTPUT` and `SYS$ERROR` through `FormattedOutput.Mod` and
  `LineOutput.Mod`, a record for each `Ln` (section 14, item 2, and
  section 15, proposal 8). `IsConsole` asks `$GETDVIW` whether the
  stream is a terminal (section 19.7, proposal 3). `Card` and `CardHex`
  write a CARD's value (section 20.1, proposal 9). `Err`'s take a
  `CardinalTypes.Card64`.
- `CardinalTypes.Mod`, internal: `rtl/llvm`'s. It names `SYSTEM.CARD64`
  for `Err`, as voc builds `Err` for Stage 0 (section 20.1, proposal 9).
- `FormattedOutput.Mod`, internal: `rtl/llvm`'s formatting that `Out`
  and `Err` share, with `LineOutput`'s stream in place of a file
  descriptor; the text of a real is `FormattedText`'s (section 19.9,
  proposals 1 and 2).
- `OutStr.Mod`: `rtl/llvm`'s, a copy kept the same (fixture
  `vax-outstr`), `Out`'s output appended to a string (section 19.9,
  proposal 3).
- `In.Mod`, `InStr.Mod` and `FormattedInput.Mod`: `rtl/llvm`'s. `In`
  reads SYS$INPUT through `Platform.Read(StdIn)`, a record at a time with
  an LF after each, with `Out`'s unfinished line as the prompt when
  SYS$INPUT and SYS$OUTPUT are terminals; `FormattedInput` reads a real
  by `DecimalToReal`; `InStr` is a copy kept the same (fixture
  `vax-instr`; section 19.11).
- `Strings.Mod`: `rtl/llvm`'s, but `StrToReal` and `StrToLongReal`
  convert by `DecimalToReal` (section 19.13).
- `Math.Mod` and `MathL.Mod`: `rtl/llvm`'s interface and errors over
  `MTH$`'s F and G routines and `OTS$`'s powers, called through
  `PocRtl`'s `POC_MATH`, which returns a signalled condition as a status
  (`LIB$SIG_TO_RET`); `arcsinh`, `arccosh` and the real-number
  properties in Oberon, from F's and G's fields; the constants F's and
  G's (section 19.15).
- `Args.Mod`: `rtl/llvm`'s, unchanged (section 19.17, proposal 1).
- `VT100.Mod`: `rtl/llvm`'s, but each sequence is followed by
  `Out.Flush`, which writes Out's line so far to a terminal without
  ending it (`POC_FLUSH_OUTPUT`), so that it reaches the screen when it
  is sent (section 19.17, proposals 2 and 3).
- `Texts.Mod`: `rtl/llvm`'s, but `Scan` converts a real by
  `DecimalToReal`, the bits of a real are F_floating's and G_floating's,
  and `Close` keeps the old file as the version below the new one, not
  as `<name>.Bak` (section 19.19, proposal 1).
- `Oberon.Mod`: `rtl/llvm`'s, unchanged (section 19.19, proposal 2).
- `VmsArguments.Mod`, VMS's own: the structures a program builds to call
  VMS through a `["VMS"]` declaration - a `CLASS_S` string descriptor,
  `item_list_3` and `item_list_2` entries and an I/O status block, with
  exact-width fields - and `Describe`, `SetItem` and `EndList` to fill
  them (Phase 17 step 5, `doc/developer/vms-sdl-interfaces.md`, part 1,
  proposal 6).
- `vms/`, generated by `tools/sdloberon` from `STARLETSD.TLB`, not to be
  edited: a module for each SDL `MODULE` node, with VMS's constants
  (`SSDEF`, `IODEF`, `JPIDEF` ...), record types (`FABDEF.FABDEF`), and
  `["VMS"]` declarations of the system services and `LIB$` and `STR$`
  routines (`STARLET`, `LIB_ROUTINES`, `STR_ROUTINES`). They make the
  library `VMSDEF`, apart from `POCRTL` (Phase 17 step 5,
  `doc/developer/vms-sdl-interfaces.md`, part 2).
- `FormattedText.Mod` and `RealDigits.Mod`: `rtl/llvm`'s, internal, for
  F_floating and G_floating. `RealDigits` takes a G_floating value apart
  for its exact digits, and `FormattedText` tests a real without IEEE
  754's bits and squares `Ten`'s powers only while it needs them
  (section 19.7, proposals 1 and 2).
- `DecimalToReal.Mod`, internal: the F_floating or G_floating value
  nearest a decimal numeral, ties to even, by
  `src/front/DecimalToDouble.Mod`'s exact method (section 19.7,
  proposal 4).
- `Reals.Mod`: voc's and `rtl/llvm`'s interface for F and G. `Ten` and
  `TenL` come from `DecimalToReal`, the largest value beyond the range.
  The exponent fields are the VAX's own, and `ConvertH` writes F's and
  G's bytes (section 19.7, proposal 5).
- `Modules.Mod`: `rtl/llvm`'s whole interface but `Init` (section 19.5,
  Phase 17 step 3). It has the command line of a foreign command, split
  as DCL quotes it, with `ArgVector` as C's `argv`. It has the list of
  modules and their commands, from the descriptors the VAX backend
  writes and `POC_MODULE` registers (`ThisMod`, `ThisCommand`, `Free`).
  It has voc's `Halt` and `AssertFail`, and `BinaryDir` (the image's
  device and directory) and `MainStackFrame`. Earlier, the command line
  alone (section 15, proposal 6; section 16, proposal 6).
- `Console.Mod` (`Flush`, `Char`, `String`, `Ln`, `Bool`, `Int`, `Hex`):
  `rtl/llvm`'s `Console`, writing to `SYS$OUTPUT` through
  `LineOutput.Mod` into the same line as `Out` (section 16, proposal 6).
- `Platform.Mod`: voc's and `rtl/llvm`'s whole interface (section 19.1,
  Phase 17 step 3): files by handle in a table of 32 (Stream_LF ones by
  block I/O, others read a record at a time with an LF after each),
  identities and revision dates, the clock, logical names and, where
  there is none, DCL symbols (`LIB$GET_SYMBOL`, section 19.19, proposal
  3), the default directory, a command in a subprocess (`LIB$SPAWN`), memory, and the
  error tests over RMS and system-service statuses; `StdOut` and
  `StdErr` go through `LineOutput`. Earlier, `GetEnv`, `Unlink`,
  `System` and `Exit` (section 15, proposals 3 and 5 to 8).
- `Directories.Mod` (`pathSeparator`, `MakePath`, `MakeSubdirectory`,
  `NameStart`, `IsDirectory`, `MakeDirectory`, and `Search`,
  `StartSearch`, `NextFile` for wildcards): directories, and the names
  of the files in them, as VMS writes them (section 15, proposal 4;
  section 18.5).

- `Files.Mod`: voc's and `rtl/llvm`'s whole interface (section 19.3,
  Phase 17 step 3). The files it makes are Stream_LF, written and read by
  block I/O; a file of another record format is read a record at a time,
  an LF after each (section 15, proposal 2). `Old` opens to read and the
  first write reopens to write, so that reading keeps a file's revision
  date; `New` fixes its name when given, and `New("")` is a file never
  registered (section 19.20); the search path is VMS
  directories; the typed riders write IEEE reals, converted from
  F_floating and G_floating; every File is finalized.
- `GarbageCollectedHeap.Mod` (`Allocate`, `Collect`, `SetStackBase`,
  `SetHeapLimit`, `SetChunkSize`, `SetMarkStackCapacity`,
  `CollectionCount`, `HeapBytes`, `LiveBytes`, `IsAllocated`,
  `RegisterFinalizer`, `FinalizeAll`): `rtl/llvm`'s collector, which
  `NEW` allocates from; `-build` adds it to a program that calls `NEW`.
  Its heap stops at three quarters of the paging file quota left when it
  starts (section 15, proposal 9).
